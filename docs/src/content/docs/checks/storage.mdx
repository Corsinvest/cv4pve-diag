Checks on every storage, on each node that can use it. How to read the codes: [Overview](/cv4pve-diag/checks/).

## Availability

| Code | SubContext | Gravity | Description |
|---|---|---|---|
| `CS0001` | Status | <Severity level="Critical" /> | Storage is not accessible on a node (shared storages are checked on every node) |
| `WS0008` | Status | <Severity level="Warning" /> | Storage is disabled but an enabled backup job or a guest still uses it |

## Capacity

| Code | SubContext | Gravity | Description |
|---|---|---|---|
| `WS0009`/`CS0009` | Usage | <Severity level="Warning/Critical" /> | Storage usage above configured threshold |
| `WS0004` | ThinOvercommit | <Severity level="Warning" /> | Disk space allocated to guests exceeds the capacity of a thin storage (LVM-thin and ZFS per node, Ceph RBD and CephFS for the cluster; container mount points `mp*` excluded) |
| `WN0044`/`CN0044` | Zfs | <Severity level="Warning/Critical" /> | ZFS pool disk usage above configured threshold |

## Backups and orphaned data

| Code | SubContext | Gravity | Description |
|---|---|---|---|
| `WS0003` | Backup | <Severity level="Warning" /> | Backup files whose VMID no longer exists (one finding per VMID and storage) |
| `WS0006` | Backup | <Severity level="Warning" /> | No storage has 'backup' content type — backups cannot be stored |
| `WS0007` | Backup | <Severity level="Warning" /> | Enabled backup job storage not enabled on a node it runs on — VMs there not backed up (a storage enabled but not reachable is `CS0001`) |
| `WS0002` | Image | <Severity level="Warning" /> | Disk image or container volume not attached to any VM/CT on that node |

Any of these can be hidden with an [ignore rule](/cv4pve-diag/ignored-issues/) on its code.

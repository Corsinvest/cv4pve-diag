Checks run on every node of the cluster. Cross-node checks compare each node with its peers and are skipped on a single node. How to read the codes: [Overview](/cv4pve-diag/checks/).

## Versions, updates and vulnerabilities

| Code | SubContext | Gravity | Description |
|---|---|---|---|
| `WN0003` | EOL | <Severity level="Warning" /> | Installed PVE version has reached end of life |
| `WN0004` | Subscription | <Severity level="Warning" /> | Node has no active Proxmox VE subscription |
| `CN0002` | PackageVersions | <Severity level="Critical" /> | A package installed on both nodes has a different version (kernel images and `pve-manager` ignored: the Proxmox VE version is `WC0011`) |
| `IN0001` | Update | <Severity level="Info" /> | Packages available for update |
| `WN0012` | Update | <Severity level="Warning" /> | Packages with APT priority `important` available for update |
| `WN0013` | Reboot | <Severity level="Warning" /> | A newer kernel is installed than the one running: reboot needed |
| `WN0042`/`CN0042` | CVE | <Severity level="Warning/Critical" /> | A known CVE affects the installed Proxmox VE version |

## Consistency across nodes

| Code | SubContext | Gravity | Description |
|---|---|---|---|
| `WN0005` | Hosts | <Severity level="Warning" /> | `/etc/hosts` entries differ between nodes (comments and spacing ignored) |
| `WN0006` | DNS | <Severity level="Warning" /> | DNS configuration differs between nodes |
| `WN0007` | Timezone | <Severity level="Warning" /> | Timezone differs between nodes |
| `WN0008` | AptRepositories | <Severity level="Warning" /> | Enabled APT repository URLs differ between nodes (suites and components are not compared) |
| `WN0014` | NTP | <Severity level="Warning" /> | Node clock differs by more than 60 s from the clock of the machine running cv4pve-diag |
| `WN0045` | NTP | <Severity level="Warning" /> | Node clock drifts > 5s from another cluster node (corosync / HA / log correlation risk) |
| `WN0015` | CPUCompatibility | <Severity level="Warning" /> | Nodes have different x86-64 feature levels: live migration may fail |

## Services, certificates and firewall

| Code | SubContext | Gravity | Description |
|---|---|---|---|
| `WN0002` | Status | <Severity level="Warning" /> | Node is not reachable |
| `WN0001` | Firewall | <Severity level="Warning" /> | Cluster firewall enabled but individual node has it disabled |
| `WN0011` | Service | <Severity level="Warning" /> | A required system service is not running |
| `CN0003` | Certificates | <Severity level="Critical" /> | TLS certificate has expired |
| `WN0023` | Certificates | <Severity level="Warning" /> | TLS certificate expires within 30 days |
| `IN0004` | Certificates | <Severity level="Info" /> | Web UI (port 8006) uses the default Proxmox certificate or a self-signed one |
| `IN0002` | IOMMU | <Severity level="Info" /> | IOMMU disabled: PCI passthrough will not work |

## Network

| Code | SubContext | Gravity | Description |
|---|---|---|---|
| `WN0009` | Network | <Severity level="Warning" /> | Physical NIC MTU differs between nodes |
| `WN0010` | Network | <Severity level="Warning" /> | Physical NIC in use (bridge, bond, VLAN or own IP) is down |
| `WN0034` | Network | <Severity level="Warning" /> | Bond has fewer than two slaves: no link redundancy |
| `WN0046` | Network | <Severity level="Warning" /> | VM/CT uses a VLAN (tag or trunk) not in the `bridge-vids` of its VLAN-aware bridge |
| `WN0047` | Network | <Severity level="Warning" /> | Bridge used by a VM/CT is missing on another node: migration / HA recovery fails |

## Resource usage

| Code | SubContext | Gravity | Description |
|---|---|---|---|
| `IN0003` | Consolidation | <Severity level="Info" /> | Node CPU and RAM utilization both below threshold: consider consolidating VMs |
| `WN0036` | Memory | <Severity level="Warning" /> | Sum of RAM allocated to VMs and containers exceeds physical node RAM |
| `WN0027`/`CN0027` | Usage | <Severity level="Warning/Critical" /> | CPU usage above configured threshold |
| `WN0038`/`CN0038` | Usage | <Severity level="Warning/Critical" /> | Memory usage above configured threshold |
| `WN0039`/`CN0039`, `WN0040`/`CN0040` | Usage | <Severity level="Warning/Critical" /> | Network throughput above configured threshold |
| `WN0028`/`CN0028` | Usage | <Severity level="Warning/Critical" /> | CPU IOWait above configured threshold: indicates storage bottleneck |
| `WN0029`/`CN0029` | Usage | <Severity level="Warning/Critical" /> | Node root filesystem usage above configured threshold |
| `WN0030`/`CN0030` | Usage | <Severity level="Warning/Critical" /> | Node SWAP usage above configured threshold: indicates RAM pressure |
| `WN0031`/`CN0031` | Pressure | <Severity level="Warning/Critical" /> | Linux PSI CPU pressure above threshold (PVE 9.0+) |
| `WN0032`/`CN0032` | Pressure | <Severity level="Warning/Critical" /> | Linux PSI I/O full pressure above threshold (PVE 9.0+) |
| `WN0033`/`CN0033` | Pressure | <Severity level="Warning/Critical" /> | Linux PSI memory full pressure above threshold (PVE 9.0+) |
| `WN0048`/`CN0048` | HealthScore | <Severity level="Warning/Critical" /> | Composite health score below threshold |

Any of these can be hidden with an [ignore rule](/cv4pve-diag/ignored-issues/) on its code.
